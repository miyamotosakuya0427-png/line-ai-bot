# 第11段階・第3工程：申請書類自動化基盤

## 実装範囲
jarvis/core/grant-document-automation.js は、原本を上書きしない読取・証跡・照合プリミティブです。

- PDF: PDF.jsでページ単位のテキスト、テキスト項目のページ番号と座標を抽出。テキスト層がないページは OCR_REQUIRED。OCRは外部アダプターを明示注入した場合だけ実行し、OCRエンジンや日本語モデルが未接続なら読めたと偽らない。
- Excel: ExcelJSで複数シート、非表示シート、セル番地、値、数式、数式結果、結合範囲、印刷設定を取得。
- Word: JSZipでDOCX内の本文・表・ヘッダー・フッターXMLを読み、段落・表セルとXMLパート位置を記録。
- 全形式: SHA-256、ファイルサイズ、文書ID、保存参照、抽出バージョンを記録。ファイル本文や個人情報をログに出力しない。
- 会社情報: 必須17フィールドを初期 UNKNOWN として作成。証明書由来の値・ハッシュ・検証者・確認日・有効期限・信頼度を保持。
- 照合: MATCH / MISMATCH / UNKNOWN / EXPIRED。UNKNOWNをMATCHに昇格しない。
- 必要書類: 制度の公式要件を呼び出し元から明示的に渡す。公募要領にない書類を自動で必須扱いしない。
- 転記マッピング: VERIFIEDかつ有効な証拠がある値のみ候補として返し、それ以外は空欄・要確認にする。公式様式への書き込みは第4工程の対象。
- 独立監査: ハッシュ・必須項目を再検証し、監査関数自体は常に readyForApproval:false を返す。別ジョブ・別コンテキストでの実行と本人承認は後続統合が必要。

## 制約・未完了
- スキャンPDFの日本語OCRエンジンは未接続。OCRアダプターを差し込める状態にし、未接続時は OCR_REQUIRED で停止。
- 会社情報マスターはこの工程で構造・照合関数を実装した段階。証明書原本の保管・実データ登録・代表者確認は未実施。
- 文書の永続保管先は未接続。Neon Object Storageは当該プロジェクトの aws-ap-southeast-2 では利用不可。公開URLへはアップロードしない。
- Neon本番テーブルへの書込み、DDL、マイグレーションは行わない。DB連携アダプターもまだ未接続。
- PDFフォーム、Excel様式、Word様式へのファイル書込みは次工程。今回の buildFieldMapping は転記候補のみを生成。
- evaluateChecklist は公募要領の検証済み要件が入力されて初めて有効。制度情報の自動収集・要件抽出を完了したとは扱わない。
- 独立監査ジョブの永続キュー統合、代表者本人認証、承認対象ハッシュ固定は未実装。
- 大容量・不正な圧縮ファイルの厳格なZIP展開上限、マルウェアスキャン、ウイルス隔離、OCR精度の校正は追加検証が必要。20MB入力上限だけで安全性を保証しない。

## 安全境界
- 本モジュールからLINE、Google Sheets、Render、Neon、外部申請サイトへの通信はしない。
- 外部送信、電子署名、法的誓約、税務申告、納税、契約、購入、支払いは実行しない。
- 申請状態を APPROVED や SUBMITTED に更新しない。
- ファイルの書込み・上書き・公開アップロードを行わない。
- 代表者本人承認が確認できない場合は承認済みと記録しない。
