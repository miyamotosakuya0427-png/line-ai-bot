# ONE JARVIS Native Audio — Stage 2 implementation record

Date: 2026-11-26  
Scope: isolated iOS/iPadOS and Android development workspace. No production API connection.

## Implemented

- Expo SDK 58 native workspace under `jarvis/private-app-native/`.
- Expo Audio `~58.0.12`, using native PCM `AudioStream` rather than file-based recorder.
- iOS microphone usage disclosure and audio background mode configuration.
- Android RECORD_AUDIO, FOREGROUND_SERVICE, FOREGROUND_SERVICE_MICROPHONE and POST_NOTIFICATIONS manifest permissions.
- Expo Audio background-recording config plugin; Android's recording foreground service and persistent recording notification are generated by the plugin.
- Explicit in-app consent before OS microphone permission request.
- Visible capture state, input-level meter, manual stop, and session-end stop.
- In-memory PCM level calculation only. No audio file recording, raw PCM persistence, audio upload, transcript storage, or secret configuration.
- Fail-closed platform/consent/permission policy and automated Node tests.
- No automatic start or restart after force quit.

## Architecture decision

- iPhone/iPad and Android: React Native + Expo native application.
- Existing PWA: retained as browser fallback; not used for lock-screen listening.
- Windows: keep the existing PWA/browser client for this stage. React Native Windows is a separate native target and would require its own compatibility/build validation; do not add a second UI stack until the mobile audio engine is proven.
- Shared integration point remains the existing ONE JARVIS backend. This stage does not call it.

## Platform constraints

### iOS / iPadOS

Expo Audio documents background recording using the `audio` background mode and `allowsBackgroundRecording`. This allows recording to continue while the app is backgrounded or the screen is locked on supported device/runtime combinations. It is not an OS-level always-on hotword entitlement and does not override App Review. Apple requires background services to serve their intended purpose and explicit consent plus a clear recording indication. The app must stop on force-quit, permission revocation or unrecoverable audio interruption. App Review acceptance is not guaranteed.

### Android

Expo Audio configures a microphone foreground service, required foreground-service permissions and persistent recording notification. Android 14+ enforces microphone service type and while-in-use permission restrictions: start from a visible activity unless a documented exemption applies. Force-stop, permission revocation, OEM battery management and reboot can stop the service. No hidden restart is implemented.

### Windows

No Windows native project or microphone behavior is changed. The existing PWA/browser path remains the current client. Native Windows support can be considered later with React Native Windows, but it is not part of this mobile audio proof.

## Important limitations / not complete

- The PCM capture pipeline is a capability test only. A local Japanese wake-word model/engine is NOT bundled and no wake-word detection is claimed.
- No AVAudioSession diagnostic bridge or detailed Android audio-focus telemetry has been implemented yet.
- No iOS/Android development build or physical device was available through this GitHub-only work session. Lock-screen, call interruption, force-quit, battery, thermal, OEM and notification behavior remain unverified.
- The app has no employee authentication or JARVIS API integration. The session-end control is a local test control, not a production logout implementation.
- No iOS App Store submission or Android Play review has been attempted.
